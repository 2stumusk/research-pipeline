# 项目优化计划

## 目标
系统性优化A股研报智能筛选系统，解决架构过渡期遗留问题、文档混乱、配置管理等核心问题。

## 发现的问题分类

### 高优先级（关键影响）
1. **架构不一致** - Codex CLI残留引用与新LLM架构共存
2. **文档混乱** - 多个重复/过时文档，用户体验差
3. **依赖版本管理** - 版本范围过宽，缺少锁定文件
4. **成本追踪未集成** - cost_tracker已实现但未在主流程使用

### 中优先级（质量改进）
5. **日志管理** - 缺少日志轮转和保留策略
6. **错误处理** - 部分错误处理不完善
7. **配置验证** - 缺少配置文件验证工具
8. **测试覆盖** - 测试套件需要验证和改进

### 低优先级（长期改进）
9. **文件命名** - 中英文混用影响跨平台
10. **安全增强** - API密钥加密存储、PDF安全检查
11. **并发优化** - 改进数据库锁的超时处理

## 实施策略

### Phase 1: 架构清理与文档整合
**目标**: 统一架构，清理遗留代码，整合文档

**任务**:
1. 清理Codex CLI残留引用
   - 更新 pipeline.py 中的错误消息和注释
   - 更新 prompts/*.md 中的术语
   - 保留向后兼容层但标记为deprecated
   
2. 文档整合
   - 删除 `问题诊断报告.md` 和 `修复完成报告.md`（已过时）
   - 合并 QUICKSTART.md, SIMPLE_START.md, 使用流程.md
   - 更新 README.md 为单一权威文档
   - 创建 docs/ 目录结构：setup.md, usage.md, troubleshooting.md

3. 配置文件管理
   - 删除 config.example.yaml（与 config.v0.2.yaml 重复）
   - 明确配置加载顺序文档
   - 添加配置验证命令

### Phase 2: 成本追踪与日志管理
**目标**: 集成成本追踪，改进日志系统

**任务**:
1. 集成 CostTracker
   - 在 LLMAdapter 中集成 CostTracker
   - 在 pipeline.py 运行结束时输出成本摘要
   - 保存成本数据到 run metadata

2. 日志轮转
   - 实现基于大小和时间的日志轮转
   - 添加日志保留策略（默认30天）
   - 在 cli.py 中配置 RotatingFileHandler

3. 改进错误处理
   - 优化 runner.available() 检查
   - 改进 API key 缺失时的用户提示
   - 添加更详细的错误上下文

### Phase 3: 依赖与测试
**目标**: 锁定依赖版本，验证测试

**任务**:
1. 依赖管理
   - 收紧 requirements.txt 版本范围
   - 生成 requirements.lock 文件
   - 更新 README 中的安装说明

2. 测试验证
   - 激活虚拟环境运行测试套件
   - 修复失败的测试
   - 添加成本追踪和日志轮转的测试

3. 配置验证工具
   - 添加 `python -m research_pipeline validate-config` 命令
   - 检查必需字段、路径有效性、API key等

### Phase 4: 文档完善与最终清理
**目标**: 完善文档，清理临时文件

**任务**:
1. 更新所有文档
   - 更新安装指南
   - 更新配置说明
   - 添加成本估算和优化指南
   - 添加故障排除指南

2. 清理临时文件
   - 清理 .venv.backup
   - 清理 build/ 目录
   - 更新 .gitignore

3. 最终验证
   - 端到端测试（demo模式）
   - 文档审查
   - 生成优化总结报告

## 不包含的内容

以下问题标记为未来改进，本次优化不包含：

- 文件重命名（中英文标准化） - 涉及大量用户脚本修改
- API密钥加密存储 - 需要额外的密钥管理系统
- PDF安全检查 - 需要引入新的安全扫描库
- 深度并发优化 - 当前实现已足够

## 实施原则

1. **向后兼容** - 保持现有API和配置格式兼容
2. **渐进式改进** - 每个阶段独立可验证
3. **文档驱动** - 所有改动都要更新文档
4. **测试保护** - 确保测试通过后再继续
5. **用户体验优先** - 改进错误消息和帮助信息

## 预期成果

1. **清晰的架构** - 统一使用新LLM架构，无遗留引用
2. **完整的文档** - 单一、清晰、最新的文档体系
3. **可靠的依赖** - 锁定版本，可重现的环境
4. **成本可见** - 每次运行都显示成本统计
5. **健壮的日志** - 自动轮转，易于调试
6. **更好的错误处理** - 清晰的错误消息和恢复建议

## 风险与缓解

**风险**: 修改核心代码可能引入新bug
**缓解**: 
- 充分测试每个改动
- 保留向后兼容层
- 提供回滚说明

**风险**: 文档更新可能遗漏重要信息
**缓解**:
- 保留旧文档作为参考
- 逐步迁移内容
- 请用户review

**风险**: 依赖版本锁定可能阻止安全更新
**缓解**:
- 定期review和更新锁定文件
- 在文档中说明更新流程
- 监控依赖的安全公告
